# 360度評価システム デスクトップアプリ

各事業所の共有PCにインストールして使う、評価入力用のクライアントアプリです(要件定義書 5章・7.3)。
Electron製で、360度評価API(`../src/`)とHTTPS通信するだけで、Googleスプレッドシートや
Googleアカウントの認証情報はこのアプリ自身には一切持ちません。

## できること

- ログイン(社員番号・パスワード)
- 評価対象者一覧の表示、評価済み/未評価の進捗表示(F-02, F-06)
- 通常評価(大項目2×小項目5+自由記述2)・代表向け簡易評価(自由記述1のみ)の入力(F-03, F-10)
- 評価結果の送信、二重送信時の上書き確認(F-04)
- **起動時の自動更新チェック**: Google Drive上の指定ファイルと画面コードのバージョンを比較し、
  古ければ自動でパッチを当ててから起動する(下記「起動時の自動更新」参照)

## セットアップ

```bash
cd desktop-app
npm install
```

初回起動時、`config.example.json` から `config.json` が自動でコピーされます。
`config.json` を開き、`src/` をデプロイして得られたWeb アプリのURLに書き換えてください。

```json
{
  "apiBaseUrl": "https://script.google.com/macros/s/xxxxxxxx/exec"
}
```

`src/` のデプロイ手順はリポジトリ直下の `README.md` を参照してください。まだデプロイしていない場合、
ログイン時に接続エラーになります。

## 起動

```bash
npm start
```

## マスタデータ(評価項目・評価期間)の更新について

評価基準(部門マスタ・部署マスタ)や評価期間は、このアプリの中には一切持たせていません。
ログイン時に毎回 `getMaster` を呼び出してスプレッドシートの最新内容を取得する設計のため、
**評価専用マスタのスプレッドシートを編集すれば、次にこのアプリでログイン(または再ログイン)した
時点で自動的に反映されます**。アプリ自体の再配布・再インストールは不要です(要件定義書 7.5)。

ログインしたまま長時間開きっぱなしにする場合、一覧画面を再読み込みしたい時は一度ログアウトして
再ログインしてください(トークンは8時間で自動的に失効します)。

## 起動時の自動更新(画面コードのパッチ配信)

「アプリを再配布せずに画面の不具合修正・改善を全PCへ配れるように」という目的で、起動のたびに
以下を行います。

1. `getAppUpdate` action を呼び、Google Drive上の指定ファイル(JSON)に書かれたバージョンと
   画面コード(`index.html` / `renderer.js` / `styles.css`)を取得する
2. 取得したバージョンが、このPCに保存済みのバージョンより新しければ、内容をユーザーデータ
   フォルダ(`patched-app/`)に書き込み、次回以降そちらを読み込むようにする
3. 画面に「更新しました」または「最新版です」を一瞬表示してから、通常の画面(ログイン画面)を開く

**このアプリ自身(Electron本体・`main.js`・`preload.js`)は更新対象に含みません。** ロック中の
実行ファイルを書き換える処理は信頼性を作り込むのが難しいため、対象は画面のHTML/JS/CSSだけに
絞っています。IPCの仕様(`main.js`/`preload.js`)自体を変える必要がある場合は、アプリの
再配布(このフォルダごと配り直す)が必要です。

オフラインなどでチェックに失敗した場合は、更新をスキップしてそのまま(前回パッチ適用済み、
なければ同梱の)画面を表示します。アプリがクラッシュすることはありません。

### 更新の公開方法(本部側の作業)

デスクトップアプリはGoogleの認証情報を持たないため、Driveには直接アクセスしません。代わりに
360度評価API(`src/`)がサーバー側でDriveファイルを読み、その内容を返します。

1. `src/` のスクリプトプロパティ `APP_UPDATE_DRIVE_FILE_ID` に、更新パッチ用のDriveファイルの
   IDを設定しておく(初回のみ。ファイルは `{"version": "x.y.z", "files": {"index.html": "...",
   "renderer.js": "...", "styles.css": "..."}}` という形式のJSON)
2. 画面コードを変更したら、`version` を上げた新しいJSONを作り、**同じDriveファイルの内容を
   「新しいバージョンをアップロード」で置き換える**(ファイルIDを変えないこと。IDが変わると
   スクリプトプロパティの再設定が必要になる)
3. 各PCは次回起動時に自動でこのバージョンを検知し、パッチを適用する
